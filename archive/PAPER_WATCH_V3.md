# Paper Watch v3：主题驱动的持续文献地图

版本：3.0｜制定日期：2026-10-23

目录：[目标](#目标) · [保留的规则](#保留的规则) · [知识结构](#知识结构) · [每轮执行](#每轮执行) · [通知结构](#通知结构) · [系统方案回忆](#系统方案回忆) · [关系与判断](#关系与判断) · [回忆机制](#回忆机制) · [归档与核验](#归档与核验)

## 目标

从“哪些新论文值得读”升级为“长期研究问题的解法、证据与系统方案发生了什么变化”。单篇评审继续保留，但主题综合成为默认阅读入口。

成果不是更长的论文列表，而是能够回答：问题怎样被分解、有哪些并行路线、每条路线改变哪个变量、哪些证据真正区分它们、当前方案应保留什么或改变什么。

不把地图做成万能流水线；不要求用户每天配置新工具、复现新模型或完成测验。沿用已有 GitHub canonical notes 与 alphaXiv 收藏。

## 保留的规则

- 原范围：计算摄影、RAW/HDR/TM/ISP、真实与生成式恢复、IQA/Reward、Agentic restoration、Pseudo-GT、Preference Optimization、高效训练及相关 benchmark/challenge。
- 核心学者/团队与开放检索并行；不得因当前项目有某个堵点而排除独立有价值的新方向。
- 先核对最早可核验公开证据、论文身份/别名、版本和历史通知。不把新发现的旧论文当新作；正式发表或新版本只有产生实质改变才标 Update。
- 保持条件通知：没有符合原高价值门槛的新论文/实质更新则静默；老文献整理、收藏补同步及周期回忆不单独伪装为新论文提醒。
- 保留 v2 的 claim decomposition、机制级 prior-art 对照、替代解释、load-bearing ablation、证据审查与 GO/GO-E/PROBE/WATCH/KILL。新颖性与工程/数据/反证价值分开判断；不以“与前作相似”自动否定工程贡献。
- 不以录用会议、作者声望、论文数量或单一指标替代证据。不强行把所有论文落成“新的范式”。

## 知识结构

1. **系统总图**：[LITERATURE_MAP.md](../LITERATURE_MAP.md)，六个长期主题 T01–T06 与横向效率层 X01。主题不是互斥标签。
2. **主题状态**：问题定义、非目标、核心路线、机制差异、锚点论文、支持/反对证据、当前判断、开放瓶颈。初版保存在总图中；材料足够后才拆主题页，避免空模板扩张。
3. **论文卡片**：继续复用 `papers/<canonical-id>.md` 或原 canonical path；包含快速回忆和精读证据，不在主题页复制全文。
4. **方案与决策记录**：记录文献导致的保留/替换/新增/暂不采用。外部研究综合可公开；私人项目进展和内部实验保留在用户授权的项目或私有位置，不能自动公开。

文献条目只是证据节点；论文之间是否有关系，需要说明具体命题。地图首要对象是长期问题、竞争路线和判断，不是作者简称。

## 每轮执行

### A. 恢复上下文

读取 ARCHIVE_PROTOCOL.md、registry、LEGACY、LITERATURE_MAP.md 和受影响的旧卡片。可访问的已有主题图/索引应优先复用，不从零另建一套。

查明本次真实成功检索窗口，不使用自动任务 last_run_time 冒充已完整检索。来源不可访问时保留覆盖缺口，不能写“已确认没有新工作”。

### B. 扫描与独立评审

沿用原领域覆盖、团队检索及开放探索。先看新工作是否通过原通知门槛，再做用户项目映射。每篇拆成不含作者命名的一句话机制，查同问题、同机制、同抽象思想的前序及更简单替代解释。

核验层级分别记录：metadata / abstract / selected sections / full paper / independent reproduction。摘要不支持完整方法、表格或因果结论。历史助手输出与本仓库旧笔记都只是追索入口，不是新事实的一手证据。

### C. 定位地图变化

为合格论文指定主要 Topic ID、次要连接及系统角色（采集/目标/数据/执行/评价/策略/训练/部署）。从以下类型选择实际变化，不强迫每篇都改变结论：

| 类型 | 含义 | 处理 |
|---|---|---|
| New route | 打开以前未覆盖的解法或问题 | 增加分支并比较竞争路线 |
| Supporting evidence | 在新条件下加强已有判断 | 补证据，不重复写成突破 |
| Boundary refinement | 缩小或明确适用范围 | 修改条件与失败边界 |
| Counter-evidence | 在相关可比条件下挑战旧主张 | 降级/撤回对应判断，保留历史 |
| Bridge | 连接原先分开的主题或接口 | 标识连接和未验证接口 |
| Engineering maturity | 算法走向可复用代码/真实系统/部署 | 更新成熟度，方法创新评级可不变 |
| No material map change | 有一定价值但不改变路线认识 | 入支持/观察池，不制造地图更新 |

### D. 重建主题理解

通知涉及的主题先用少量文字恢复旧问题和 2–3 个相关锚点，再说明本次变化。旧锚点明确标历史上下文，不计为新推荐。

每个主题主视图通常保留 3–5 条核心路线、3–5 篇记忆锚点。细节进入完整索引；不能把最近发表的所有论文挤成主节点。锚点因解释力和证据变化替换，不因日期旧自动淘汰。

解释机制应覆盖：输入、输出、控制变量、训练监督、推理动作、成立条件、失败例子。不能只罗列“用了 diffusion / VLM / reward”。

### E. 连接到系统方案

从已有计划/真实实验记录恢复当前方案，逐项标记 literature-supported / proposed / implemented / empirically-validated / unknown。论文里的有效性不能提升为用户项目已验证。

对本次更新明确回答：改数据、目标、执行器、搜索、选择器、训练还是部署？是替换原组件还是增加一个对照？什么条件不成立时应保留旧方案？

完整方案有两张视图：在线推理链与离线训练/数据链。Agent 是控制层，不应把数据生成器、评价器、训练教师和部署执行器混成一个必需大模型。若只是可行组合假设，明确标“待验证组合”，不写成文献已经证明的系统。

### F. 保存与回读

实际更新 canonical card、受影响主题段落及简短 changelog；遵循已有 registry 事件与并发写入规则。新增数据/方法的论文卡片才增加身份记录；仅改变地图结构不伪造新论文事件。

## 通知结构

每天仍最多 1–5 篇新论文，默认按受影响最大的 1–3 个主题组织。正文优先讲透一条主线，其余只给必要增量；不要把旧的每篇长报告再完整叠加。

```text
本轮改变了哪 1–3 项认识？

Topic / 长期问题
1. 旧地图：问题、竞争路线、2–3 个历史锚点。
2. 新证据：新论文/作者/首次公开与版本；抽象命题、真实增量、关键证据及限制。
3. 地图变化：新增/支持/边界修正/反证/连接/工程成熟；明确旧→新判断。
4. 当前完整方案：在线链、离线链、改动处、仍未验证的接口。
5. 决策：保留/替换/新增/暂不采用；必要时只给一个最小判别实验。
6. 记忆锚点：一句机制、一个关键区别或反例。

紧凑来源与归档回执：真实 GitHub 路径、alphaXiv membership、未完成项。
```

每篇仍保留作者主张、局部证据、跨工作支持/冲突与共识状态，可收纳在主题对照表或 canonical card，不要求每项在聊天里重复铺陈。

## 系统方案回忆

一页卡需要能让读者重新画出方案，而不仅记住标题：

```text
目标和非目标：
输入/输出/必需元数据：
目标图像或偏好由谁定义：
在线路径与停止/回滚条件：
离线数据、监督与训练路径：
强非 Agent / 简单基线：
可达性 / 可发现性 / 可选择性瓶颈：
支持本接口的文献及其条件：
已实现与已验证状态（没有证据就 unknown）：
本次仅改变哪一环：
```

新工作没有触及当前瓶颈时，应明确“文献地图增加理解，当前方案暂不修改”。不要每次推荐新模型就重构项目。

## 关系与判断

关系至少区分：直接继承、共同抽象机制、竞争、互补、适用边界、反证、跨主题连接。直接继承需要原文引用或明确作者表述；分析者建立的关系注明综合/推断。发表先后不能单独证明继承。

不同论文解决不同目标、使用不同资源时，不能画“全面胜过”的箭头。更强同类结果也不自动反驳旧机制。

共识状态采用：单篇主张 / 局部支持 / 多独立工作方向 / 较稳定认识 / 仍有争议。独立团队数量是线索，不是充分条件；同时审查任务条件、证据独立性、反例和实际采用。

对“突破”记录改变了哪一个可检验限制：信息边界、目标定义、可靠监督、评价能力、可部署成本或可实现动作。只有叙事变化不算突破。

## 回忆机制

- **即时连接**：每次新论文带回少量相关旧锚点，解释同与不同，避免全文重播。
- **主题巩固**：主题在过去 7–14 天有实质积累时，在下一次符合通知条件的报告里重建该主题的一页全貌；不另开定时任务，不因到了日期强行通知。
- **主动回忆**：必要时最多附一个可选问题，如“这个方法改变了输入侧还是目标侧？”或“有 GT 的评价能否部署到无 GT 场景？”不把阅读/收藏当作掌握证据，不固定增加测验负担。
- **保留竞争方案**：完整认知意味着能说出至少一个强替代解释和失效条件，而非只记推荐立场。

## 归档与核验

GitHub 维护主题地图与唯一技术正文；alphaXiv 维护论文入口和主题收藏；已有私有阅读入口只保留导航与用户批注，不复制第二套长文。

GO/GO-E/PROBE 的已核验论文按已有偏好同步 alphaXiv：先查 membership、保存到适当现有主主题、保留用户阅读状态、回查结果。WATCH/KILL 默认不保存。没有新增论文时不重复收藏旧锚点。当前连接器无自定义笔记写入能力时，不声称已同步完整研究笔记。

遵循 ARCHIVE_PROTOCOL.md 的公开/私有边界；实际写入失败记录 pending，不把生成文本当作同步成功。不修改其他自动任务、运行时间、时区、启用状态或客户端通知偏好。

v3 配置生效不代表未来每次运行必定有全部连接器权限。每轮以实际读写回执为准。
