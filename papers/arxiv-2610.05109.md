# LoopMoEVR：循环 MoE 的统一 UHD 视频恢复

- **身份**：arXiv:2610.05109
- **首次公开（已核）**：2026-10-04，v1
- **本次核验**：2026-10-09；selected sections checked
- **独立复现**：未进行

## 快速回忆

**问题**：UHD 去噪、低照、去雨、去雾若各自使用大模型，参数、显存与维护成本高。

**机制**：共享参数的循环 MoE，配合 degradation-conditioned low-rank loop embedding、时空迭代归一化和输入自适应循环深度，以一个小模型覆盖四类视频恢复。

**证据**：作者报告约 0.884M 参数，并在 UHV-4K-AIO 原生 4K 五帧窗口评价。训练硬件为 NVIDIA V100；手机 4K 示意不是移动端运行证明。

**决策边界**：参数量小不等于端到端实时；未给出手机内存带宽、算子支持、功耗、热和 capture/codec 开销。属于 RGB/UHD 恢复，不是 RAW、demosaic 或 3A。

**下一步**：转换到实际 NPU 后量测 4K 吞吐、峰值内存、功耗与长视频热降频；加入压缩、rolling shutter 与曝光切换混合退化。

## 精读记录

- **可竞争解释**：循环次数自适应可能把固定成本转成尾延迟；需同时报告平均、P95 迭代数与失败分桶。
- **工程含义**：若算子友好，适合做统一后处理骨架；若路由/循环调度不稳定，小参数优势可能被访存吞噬。
- **评价建议**：把感知增益、时序一致性、文字/人脸保真和端到端手机性能分开。
